# v1.1 release candidate security assessment

Maintainer review, October 17, 2026. This is not an independent penetration test.
Scope: PR #5 Reader plus optional Basic/Secure Draft Assistant and browser portal.

## Capability and compatibility boundaries

Reader is the default: five existing tools, unchanged read schemas and payloads,
EXAMINE and BODY.PEEK, no APPEND. Both draft policies require master opt-in; Basic
also requires its explicit acknowledgment. Browser approval is separately disabled.
No failure changes policies automatically. Secure approval is independently bound
to exact MIME, source/destination identity, checksum and expiry; Basic explicitly
records delegated client authority, not verified human approval.

The only additional permitted IMAP command is one exact APPEND on the separate
draft adapter after atomic approval consumption. Protocol dispatch denies STORE,
UID STORE, MOVE, COPY, DELETE, CREATE, RENAME, EXPUNGE, CLOSE, SELECT and other
nonallowlisted commands. Source reads use BODY.PEEK and sockets close without
CLOSE/EXPUNGE. No SMTP transport, SMTP credentials, send tools or send configuration
exists. These are application controls, not protection against a compromised host,
dependency, mailbox server, or another program using the mailbox password.

Authenticated capability discovery replaces the pre-login cache on every successful
LOGIN for both adapters. Discovery failure prevents dependent operations and
cannot inherit stale UIDPLUS. Content/approval/expiry guards are unchanged.

## Evidence

- 128 synthetic tests: Reader, Basic/Secure, real IMAP framing and stdio MCP,
  authenticated-only UIDPLUS, exact one-use APPEND, sessions/CSRF/OIDC, expiry,
  tamper/replay/concurrency, destination/source identity and uncertain-save behavior.
- Controlled live acceptance: one synthetic Secure terminal-approved draft in a
  dedicated Mailcow test mailbox; exact saved bytes, threading, destination and
  SHA-256 verified; original bytes/flags unchanged. No SMTP used. The test harness
  refreshed authenticated capabilities; the regression fix now provides that in
  the application. No broad browser/provider deployment certification is implied.
- Actual ChatGPT mock-backend UI acceptance: summarized prompts, technical Details,
  remembered permissions and permissive client settings prevent a guarantee of
  full-message review or per-save approval. Altered-content, expiry and replay
  refusals were separately observed. See [mode limits](../docs/DRAFT-MODES.md).
- Advisory audits cover runtime, optional browser and audit tooling; full-history
  hygiene scans, manual changed-file review and known-private-identifier checks
  must pass on the exact final candidate. Pattern scans cannot prove universal
  absence of sensitive data. Live transcripts, credentials and test data stay out
  of the public repository.

## Residual risks and deployment gates

1. **Host authority:** terminal approval assumes a trusted operator/host. A TTY is
   only an accidental-use guard. The drafting assistant must not have approval
   database, shell, service-account or password access. Isolate the browser UID and
   IPC broker per the browser guide. Dedicated test and production states stay apart.
2. **Plaintext staging:** private SQLite, journals and backups retain sensitive
   data. Use encrypted host storage, restricted permissions, short retention and
   protected backups. Expiry does not erase data; no encryption-at-rest claim.
3. **Stolen sessions:** browser authentication permits routine approval without a
   new passkey challenge. Use HTTPS, short sessions, logout/revocation, trusted
   devices, IdP MFA/passkeys where available and explicit review of every request.
   No fresh per-operation user-verification guarantee is implemented.
4. **IMAP race:** source/target checks and APPEND are not one atomic transaction;
   concurrent remote folder/message changes remain a residual risk. UIDVALIDITY
   and exact-byte readback detect discrepancies where possible. Uncertain results
   are never automatically retried, repaired or removed.
5. **Client trust:** Basic is unsuitable for mandatory independent approval in
   ChatGPT. It can be released only as clearly labeled operator-delegated authority;
   Claude/other interfaces remain unverified. Secure terminal is the validated
   minimal-dependency route; live browser HTTPS/IdP/recovery tests remain pending.
6. **External controls:** GitHub checks/history scans supplement native scanning,
   push protection and branch rules. Verify those hosted settings and required
   checks at merge/release time; a prior review or workflow file is not proof of
   current enforcement. Owner bypass remains possible. No secrets go into CI.

## Hosted controls observed during this review

The public GitHub API confirms main is protected by active deletion/force-push
restrictions, required PRs and strict up-to-date status checks bound to GitHub
Actions: unittest, pip-audit, repository-hygiene. It requires resolved review threads
but zero approving reviewers; independent code review is not enforced. Private
vulnerability reporting and Discussions are enabled. Public repository metadata
does not expose native secret-scanning/push-protection settings; these require
privileged verification in the authorized publication window. Do not infer their
current status from older screenshots or the presence of local hygiene checks.
No hosted setting was changed by this review.

## Recommendation

GO for final owner review of a Reader-default, opt-in v1.1 candidate with Secure
terminal support and documented Basic limitations, subject to successful exact-head
CI/audits/hygiene. No identified mandatory code fix remains from this scoped review.
NO-GO for automatic merge, production deployment, tag or publication without owner
approval. Live browser deployment, recommending Basic as guaranteed human approval,
and untested providers remain outside validated scope. Recheck the actual final
merge/release commit and hosted security controls in the authorized release window.
Naming uncertainty remains accepted, not legally cleared.
