## Findings and remaining decisions

No new blocking application vulnerability was identified in this review. Residual
risks below are explicit deployment limitations, not claims of perfect security:

- **Credential scope:** Mailcow protocol switches do not establish Sent-only/
  append-only ACLs, a fixed recipient allowlist, or every sender-alias restriction.
  Verify actual provider rights; keep new secrets exclusively under trusted sender
  ownership. Credential references hash paths, not values: in-place rotation does
  not revoke pending approvals. Reject pending proposals before credential changes.
- **Host/approval trust:** compromised root/sender/runtime/operator or AI access to
  the trusted terminal can bypass the boundary. Keep account/shell/sudo/loader and
  tracing protections; never automate confirmation. Terminal-only approval is less
  convenient; browser Send remains planned. Basic Draft client limitations remain.
- **Recovery/exactly-once:** protocol uncertainty and external auto-filing races
  cannot guarantee global exactly-once. Conservative non-retry may leave a missing
  Sent copy. Old snapshots can omit later attempts; require reconciliation before
  restoring/promoting any pending state. Preserve newest receipts and never resend
  to repair filing. No automatic retry/deletion/repair is provided.
- **Plaintext state:** live credentials/staged MIME remain plaintext behind Unix
  permissions; backup encryption does not encrypt live storage. Establish encrypted
  storage, retention and off-host key recovery for the deployment. A second offline
  recovery-key copy remains an operator responsibility, not verified by this review.
- **Operational limits:** local SQLite only;256 retained records/32 pending then
  fail closed. Socket timeouts do not provide whole-workflow IMAP/SMTP deadlines;
  these operations are trusted-operator paths, not exposed TCP endpoints. Other
  servers, Unicode/client edge cases and live browser deployment need testing.
- **Governance:** recommend requiring the Linux isolation job; no native code
  scanning certification is claimed. Final merge/release checks and explicit owner
  authorizations remain outstanding. Existing production deployment is a separate
  plan and is not approved by technical readiness.
