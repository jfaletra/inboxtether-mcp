# Sent synchronization implementation review — 2026-10-17

Scope: optional Sent filing on the existing Secure Send feature branch. Reader, Draft Assistant, SMTP transport, trusted startup, IPC dispatch authority and dependency requirements remain unchanged. No deployment or live IMAP/SMTP connection is part of this change.

## Security decisions

- Disabled by default; legacy sender configuration/scope remains valid when the new option is absent/disabled. No MCP argument can select a filing policy or destination.
- Trusted operator discovery authenticates with a separate IMAP-only secret, refreshes capabilities, requires UIDPLUS and pins the existing special-use/explicit folder plus UIDVALIDITY. Preparation remains offline, preserving the broker's AF_UNIX restriction. Pins and credential references are included in the immutable reviewed manifest; altered scope/pins invalidate pending approval.
- SMTP acceptance is persisted before filing. Filing claims have a separate atomic single-use primary key, result and recovery state. Filing/reconciliation never calls SMTP. Failed/uncertain SMTP and lost SMTP receipt writes never initiate filing.
- APPEND uses the identical submitted MIME bytes. Only read-only SELECT, UID search/size/peek verification and the single APPEND are used. Existing messages/flags remain untouched. Bcc stays in the private envelope, not copied MIME.
- Ambiguous APPEND or verification results retain uncertainty, including lost filing receipt writes. Reconciliation is read-only and exact-byte matching; absence never enables another APPEND. Historical receipts remain available after disabling/changing configuration.
- Private files require ownership0600; private state0700; no symlink secret/pin reads. The privileged Linux isolation test additionally checks actual MCP denial of a sender-owned synthetic IMAP credential.

## Validation

217 local tests: 215 passed, two privileged Linux tests intentionally skipped on macOS. Includes 33 new Sent synchronization tests covering defaults/legacy JSON, offline prep, TLS/auth capability refresh, discovery/override/malformed and Unicode/literal folders, UIDVALIDITY changes, exact MIME/attachments/threading, SMTP nonacceptance, connection/recipient-independent filing failures, concurrent claims, replay, provider-existing copies, missing/malformed APPENDUID, byte-verification failure, lost acknowledgment, lost receipts, consistent SQLite snapshot restore, changed configuration, secret/pin protections and malformed/corrupt state.

All strict runtime, browser and audit-tool dependency audits: no known vulnerabilities. Dependency consistency passed. Complete-history hygiene is required before commit and hosted checks remain authoritative for Linux privilege tests.

## Residual risks / live-test gates

Standard IMAP cannot provide generic idempotent APPEND after a connection loss. Conservative at-most-one attempts can leave a missing Sent copy; external provider auto-filing can still race. No cross-provider exactly-once guarantee is claimed. UIDPLUS is mandatory for this optional feature; missing/unavailable/ambiguous folders fail closed without folder creation.

Mailcow protocol-limited application passwords do not by themselves restrict IMAP to append-only or one folder. Actual folder ACLs/delegation must be reviewed/tested separately. The trusted sender credential can have broader mailbox authority than the application uses. Host/root/sender compromise and live plaintext staging remain outside isolation guarantees.

Before live Sent tests: independent review of this change and hosted checks; separate installation approval; new dedicated IMAP-only test credential and actual mailbox rights review; authenticated Sent discovery/UIDPLUS/UIDVALIDITY validation; update encrypted backup coverage to include the pin, new IMAP secret and both receipt tables; verify quarantine restore; inspect provider auto-filing policy; approve an exact fresh synthetic message including its Sent destination. Never restore a pre-attempt snapshot and reapprove pending records without reconciliation. No existing production/isolated application or credential has been modified for this implementation.
